## 1. 当前产品目标

`stocker` 的目标不是高频交易机器人，而是一个必须持续运行、能在模拟盘实跑并持续迭代的区间/波段交易辅助驾驶舱。它要在交易时段和用户设定的监控窗口内常驻运行，持续盯住用户真实交易决策相关的信息：第一，盯住用户已有持仓，基于成本价、现价、支撑/压力、止盈止损、趋势破位和重大新闻给出及时预警；第二，盯住用户感兴趣的方向、行业、市场和股票池，从真实行情、资金流、新闻事件中筛出值得进一步研究的候选标的；第三，在财报、评级、资金异动、价格破位、行业突发等关键事件出现时，立即提示“需要看、需要减仓、需要止损、可以等待、可以加到观察池”等操作级结论；第四，把这些预警、建议、模拟盘订单、持仓变化和结果沉淀成复盘数据，用来持续修正规则和产品优先级，而不是做完功能后无法验证有没有用。

产品优先级按“能否及时避免亏损、捕捉机会、并在模拟盘验证有效”排序：P0 是常驻运行、模拟盘实跑闭环、持仓预警、关键事件预警、可信数据和安全边界；P1 是方向推荐、股票池跟踪、交易计划、交易复盘和迭代反馈；P2 是复杂回测、前端体验和代码拆分。可以延后的是复杂多数据源兼容、高频撮合、全自动无确认实盘交易、大而全研究报告和纯架构优化。

## 3. 功能取舍

必须先做的功能是：常驻运行进程、交易时段/监控窗口配置、westock 本地模拟盘下单验收、持仓导入/同步、持仓成本与现价对比、支撑压力和止盈止损预警、重大事件影响判断、预警通知与去重、观察方向候选推荐、股票池跟踪、交易记录持久化、预警和交易结果复盘。可以往后放的是：复杂多策略回测、全自动调仓、漂亮但不影响决策的前端重构、多数据源 fallback、高频行情、跨券商抽象和大规模插件化。

## 4. 近期执行顺序

近期只围绕“能不能持续运行并在 westock 本地模拟盘产生可验证价值”推进：常驻监控、westock 模拟盘最小验收、持仓预警、去重冷却和预警转待确认交易计划已完成；下一步做关键事件影响分级和模拟盘交易结果复盘。对应顺序是：关键事件影响分级 → 模拟盘交易记录完善 → 预警与交易结果复盘 → 方向/主题候选推荐 → 股票池交易计划 → 回测路径修复 → 前端与代码拆分。

## 5. 后续维护原则

主 task-map 不记录单个函数或单个文件级修改，只维护用户需求域、目标、当前判断和明细文档入口。任何任务完成后：若改变用户需求状态或优先级，更新本文件；若只改变具体 backlog，更新 `docs/details/task-backlog-detail.md`；无论哪种，都在本文件维护记录追加摘要，并同步检查 `docs/code-dev-map.md` 是否需要更新。
